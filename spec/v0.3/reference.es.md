# Referencia de campos — OTE Spec 0.3.0

> 🤖 Generado a partir de los schemas — no lo edites a mano. Ejecuta `npm run build-reference`.
>
> Las reglas que un validador no puede comprobar (por qué el `id` no cambia nunca, por qué un evento cancelado sigue publicado) están en [README.md](README.md).

**Nivel** — `obligatorio`: sin él, el validador rechaza el documento. `recomendado`: el documento es válido sin él, pero un checker avisa — son los campos que deciden si el evento se puede encontrar, filtrar y seguir. Se leen de [`event.recommended.schema.json`](event.recommended.schema.json) y [`feed.recommended.schema.json`](feed.recommended.schema.json).

`obligatorio dentro de X` significa obligatorio **dentro de un objeto que es opcional**: un documento mínimo no necesita ninguno de los dos, pero un documento que traiga `X` tiene que dar el campo. Omitir el objeto entero sigue siendo válido.

## `event` — Evento

Un evento de una comunidad técnica.

| Campo | Tipo | Nivel | Descripción | Ejemplos |
| --- | --- | :---: | --- | --- |
| `specVersion` | const: "0.3.0" | **obligatorio** | Versión de OTE Spec a la que se adhiere el documento. | `"0.3.0"` |
| `id` | string (uri) | **obligatorio** | Identificador estable y único a nivel global. Una URI bajo un dominio que controle quien publica. Se acuña una vez y no se reescribe jamás: es lo que permite a un consumidor actualizar el evento en vez de duplicarlo. | `"https://pyalmeria.example/eventos/2026-06-async"`<br>`"https://calendar.example/ics/rust-madrid#a1b2c3d4-uid"` |
| `url` | string (uri) | _recomendado_ | URL canónica donde se describe el evento hoy. Puede cambiar con el tiempo; el `id` no. | `"https://pyalmeria.example/eventos/2026-06-async"` |
| `name` | string | **obligatorio** | Nombre del evento. | `"PyAlmería — Introducción a async/await"` |
| `description` | string | _recomendado_ | Descripción breve. Texto plano o Markdown. | `"Charla introductoria a la programación asíncrona en Python, con ejemplos en vivo."` |
| `image` | (string \| object)[] | _recomendado_ | Imágenes promocionales del evento: cartel, portada, tarjeta. Es una lista en orden de preferencia — la PRIMERA es la principal, y a menudo la única que un destino puede usar. Las demás pueden ser otros recortes o resoluciones de esa misma imagen (Google pide 1:1, 4:3 y 16:9) o imágenes distintas; quien solo pueda mostrar una, muestra la primera, y nadie debe dar por hecho que la lista se renderiza como galería de fotos. Cada entrada es o bien una URL https pelada al fichero de imagen —nunca a una página que la muestre— o bien un objeto que añade texto alternativo. | `["https://rustmadrid.example/img/2026-06-16x9.png"]`<br>`[{"url":"https://rustmadrid.example/img/2026-06-16x9.png","alt":"Cartel: Ferris sobre fondo morado, «Rust Madrid · 16 junio · Impact Hub»"},"https://rustmadrid.example/img/2026-06-1x1.png","https://rustmadrid.example/img/2026-06-4x3.png"]` |
| `image[].url` | string (uri) | **obligatorio** dentro de `image[]` | URL https absoluta del fichero de imagen, nunca de una página que la muestre. El mismo valor que lleva la forma de cadena pelada. | `"https://rustmadrid.example/img/2026-06-16x9.png"` |
| `image[].alt` | string | opcional | Lo que la imagen MUESTRA, para quien no puede verla: lectores de pantalla, clientes de solo texto y cualquier render donde la imagen no cargue. Describe la foto, no el evento — el `name` y la `description` ya se están leyendo al lado, así que repetirlos hace que un lector de pantalla diga dos veces lo mismo. Sin «imagen de» ni «cartel que muestra»: el cliente ya anuncia que es una imagen. Se escribe en el `textLanguage` del documento, como el resto del texto libre, y se traduce con el mapa `translations` de esta misma entrada: el `alt` se lee en voz alta con la pronunciación del idioma que lo rodea, así que un `alt` en inglés dentro de un documento en español es peor accesibilidad que el problema que venía a resolver. Una imagen puramente decorativa no pinta nada en un feed, y aquí no hay cadena vacía: una imagen que no tiene nada que decir es una imagen que se deja fuera. | `"Cartel: Ferris sobre fondo morado, «Rust Madrid · 16 junio · Impact Hub»"`<br>`"Sala diáfana con unas 60 sillas y una pantalla al fondo"` |
| `image[].translations` | object | opcional | El `alt` de esta imagen en otros idiomas. Local a la imagen que describe — nunca un espejo posicional de la lista de imágenes. Exige el `textLanguage` del documento, como cualquier otro mapa de traducciones. | `{"en":{"alt":"Poster: Ferris on a purple background, “Rust Madrid · June 16 · Impact Hub”"}}` |
| `organizers` | object[] | _recomendado_ | Quién organiza el evento — no de dónde salieron los datos (eso es `source`). Es una lista: la co-organización es lo normal, no la excepción. Dentro de un feed, el evento que la omite hereda la del feed; declararla REEMPLAZA la heredada, no se suma a ella. | `[{"name":"PyAlmería","url":"https://pyalmeria.example"}]`<br>`[{"name":"GDG Madrid","url":"https://gdgmadrid.example"},{"type":"person","name":"Ada Lovelace","url":"https://ada.example"}]` |
| `organizers[].name` | string | **obligatorio** dentro de `organizers[]` | Nombre de quien organiza. | `"PyAlmería"`<br>`"Ada Lovelace"` |
| `organizers[].url` | string (uri) | opcional | Dónde vive en la web quien organiza: su propia página, o su perfil en la plataforma desde la que publica. | `"https://pyalmeria.example"`<br>`"https://www.meetup.com/pyalmeria/"` |
| `organizers[].email` | string (email) | opcional | Dirección de contacto para preguntas sobre el evento. Una dirección DE ROL (`info@`, `hola@`), no el buzón personal de nadie: un feed es abierto y rastreable, y lo que entra en él ya no se puede despublicar. Opcional y deliberadamente NO recomendado. Existe porque sin él no hay `ORGANIZER` de iCal válido que emitir (un `CAL-ADDRESS` es en la práctica un `mailto:`) ni `<author>` de RSS 2.0, que exige email. Se escribe pelado, sin el prefijo `mailto:` — lo añade quien exporta. Nunca se rellena a partir de una fuente que no esté publicada públicamente. | `"hola@pyalmeria.example"`<br>`"info@gdgmadrid.example"` |
| `organizers[].type` | enum: organization \| person | opcional | Organización o persona. Por defecto, organización: al traducir hay que elegir un `@type` de schema.org sí o sí, y `Organization` es la opción tolerante. | `"organization"`<br>`"person"` |
| `startDate` | string | **obligatorio** | Inicio en hora de reloj de pared: una fecha (`2026-10-15`) para eventos de todo el día, o una fecha-hora local (`2026-10-15T09:00:00`). Nunca lleva offset UTC: eso lo aporta `timezone`. | `"2026-06-11T18:30:00"`<br>`"2026-10-15"` |
| `endDate` | string | _recomendado_ | Fin en hora de reloj de pared, en la MISMA forma que `startDate` (ambas fechas, o ambas fecha-hora). Si falta, se asume que el evento termina el día que empieza. | `"2026-06-11T20:00:00"`<br>`"2026-10-16"` |
| `timezone` | string | **obligatorio** | Zona horaria IANA (p. ej. `Europe/Madrid`). Convierte un `startDate` de reloj de pared en un instante inequívoco. En eventos de todo el día contextualiza la fecha: no la desplaza. | `"Europe/Madrid"`<br>`"America/Bogota"`<br>`"UTC"` |
| `attendanceMode` | enum: in-person \| online \| hybrid | _recomendado_ | Qué dice quien organiza que es este evento. SIN VALOR POR DEFECTO: ausente significa desconocido, nunca presencial. | `"in-person"`<br>`"online"`<br>`"hybrid"` |
| `location` | object | _recomendado_ | Qué se SABE de dónde ocurre el evento. Pregunta distinta de `attendanceMode`, que declara la intención de quien organiza. | `{"venue":"El Cable, Almería"}`<br>`{"onlineUrl":"https://meet.example/pyalmeria"}`<br>`{"venue":"Campus Madrid, Calle de Moreno Nieto 2, Madrid","address":{"street":"Calle de Moreno Nieto 2","locality":"Madrid","postalCode":"28005","country":"ES"},"onlineUrl":"https://meet.example/rust-madrid"}` |
| `location.venue` | string | opcional | Lugar físico, legible por personas. Su presencia significa que el evento tiene sede física. Es la cadena que cualquier destino puede imprimir tal cual: `LOCATION` de iCal, el texto de un ítem RSS, `Place.name` de schema.org. | `"El Cable, Almería"` |
| `location.address` | object | opcional | Dirección postal de la sede física, por partes. COMPLEMENTA a `venue`, no lo sustituye: `venue` es la única cadena que todo formato sabe imprimir; `address` es lo que necesita un traductor para emitir un `PostalAddress` de schema.org — cuyos subcampos Google valida uno a uno para el rich result de `Event`. Todas las partes son opcionales; omite lo que no sepas. Una clave ausente significa desconocido; `""` o `null` publican un desconocido como si fuera dato, que es lo único peor que callarse. | `{"street":"Calle de Moreno Nieto 2","locality":"Madrid","postalCode":"28005","country":"ES"}`<br>`{"locality":"Almería","country":"ES"}` |
| `location.address.street` | string | opcional | Calle y número, tal y como se escriben localmente. Puede llevar planta o puerta; es una línea de texto, no un sub-objeto. | `"Calle de Moreno Nieto 2"`<br>`"100 West Snickerpark Dr"` |
| `location.address.locality` | string | opcional | Ciudad, pueblo o localidad. | `"Madrid"`<br>`"Almería"` |
| `location.address.region` | string | opcional | Provincia, estado o comunidad autónoma — el nivel que en ese país queda entre localidad y país. Texto libre o código ISO 3166-2; ambos viajan sin cambios a `addressRegion` de schema.org. | `"Comunidad de Madrid"`<br>`"PA"` |
| `location.address.postalCode` | string | opcional | Código postal, tal y como lo escribe el correo local. Cadena, nunca número: los ceros a la izquierda forman parte de él. | `"28005"`<br>`"19019"` |
| `location.address.country` | string | opcional | Código ISO 3166-1 alfa-2, en mayúsculas (`ES`, `US`, `MX`). Un código y no el nombre del país, porque el nombre tiene una grafía por idioma: «España», «Spain» y «Espagne» son el mismo país, y un consumidor que agrupe eventos por país vería tres. Convertir un nombre en código es consultar una tabla, no inventar — por eso la spec lo pide aquí y en ningún otro sitio. | `"ES"`<br>`"US"` |
| `location.onlineUrl` | string (uri) | opcional | URL para asistir en remoto. Su presencia significa que el evento tiene acceso online. | `"https://meet.example/pyalmeria"` |
| `location.geo` | object | opcional | Coordenadas de la sede física (grados decimales WGS-84). Independiente de `venue`, que es texto libre: un punto, no un nombre. Mapea a `GEO` de iCal y a `Place.geo` (GeoCoordinates) de schema.org. | — |
| `location.geo.lat` | number | **obligatorio** dentro de `location.geo` | Latitud en grados decimales. | `40.4168` |
| `location.geo.lon` | number | **obligatorio** dentro de `location.geo` | Longitud en grados decimales. | `-3.7038` |
| `eligibility` | object | opcional | Quién puede asistir, cuando la respuesta no es «cualquiera». La tercera parte de «¿puedo ir?», después de `attendanceMode` y `location`: esos dos dicen si el evento está a tu alcance, este si te dejan entrar. SIN VALOR POR DEFECTO: ausente significa desconocido, nunca abierto — quien importa un `.ics` no puede saberlo, y callarse no es la misma afirmación que decir que la puerta está abierta. | `{"type":"open"}`<br>`{"type":"members-only","note":"Miembros del Discord de Rust Girona","url":"https://rustgirona.example/join"}`<br>`{"type":"restricted","note":"Solo alumnado de la Universidad de Almería"}` |
| `eligibility.type` | enum: open \| members-only \| approval-required \| restricted | **obligatorio** dentro de `eligibility` | Qué clase de puerta. `open`: puede asistir cualquiera — incluido un evento con entrada de pago o con las plazas agotadas, porque un precio y un aforo no son condiciones sobre QUIÉN eres. `members-only`: hay que pertenecer a algo antes. `approval-required`: te apuntas y quien organiza DECIDE — el «request to approve» de Luma, un grupo de Meetup con pregunta de admisión, un taller que selecciona a quien asiste. Va de un juicio sobre la persona, nunca de aforo: por orden de llegada con plazas limitadas es `open`, y que se agoten es `offers[].availability`. `restricted`: HAY una condición y ninguno de los otros valores la nombra — di cuál en `note`, que es por lo que el schema la exige ahí. Cuatro valores, y cortos a propósito: un consumidor que tiene que tratar veinte puertas no trata ninguna. `invite-only` NO es uno de ellos, a propósito: ver la prosa de la spec. | `"open"`<br>`"members-only"`<br>`"approval-required"` |
| `eligibility.note` | string | opcional | La condición en palabras, para que la lea una persona: qué comunidad, qué universidad, qué empresa. OBLIGATORIA cuando `type` es `restricted`, porque «restricted» a secas no le dice nada a nadie; vale la pena escribirla siempre que el valor del enum por sí solo deje una duda. Es la parte que sobrevive a la exportación a cualquier formato, dentro del texto. | `"Miembros del Discord de Rust Girona"`<br>`"Solo alumnado de la Universidad de Almería"` |
| `eligibility.url` | string (uri) | opcional | Dónde se explica o se cumple la condición: la página para unirse a la comunidad, pedir invitación o solicitar plaza. Distinta de `offers[].url`, que es donde cambia de manos una plaza o un pago — aquí no se compra nada, se abre una puerta. | `"https://rustgirona.example/join"` |
| `eligibility.translations` | object | opcional | La `note` en otros idiomas. `type` no necesita ninguna: un enum no lleva idioma, y quien consume lo renderiza en el de quien lee. | `{"es":{"note":"Miembros del Discord de Rust Girona"}}` |
| `tags` | string[] | _recomendado_ | Etiquetas temáticas de forma libre — DE QUÉ va el evento. Mapea a `CATEGORIES` de iCal y a `keywords` de schema.org. No quién puede entrar: esa pregunta tiene su propio campo, `eligibility`, porque una etiqueta como «solo-socios» es invisible para un consumidor que no sepa ya que tiene que buscarla. Más adelante podría superponerse un vocabulario controlado; el campo en sí sigue siendo libre. Sin valor por defecto: ausente significa desconocido. | `["rust","wasm"]`<br>`["python","async"]` |
| `languages` | string[] | _recomendado_ | Idiomas que se HABLAN en el evento, como etiquetas BCP 47, p. ej. `["es","en"]`. No el idioma en que está escrito este documento — eso es `textLanguage`, y los dos no coinciden a menudo: una sesión bilingüe descrita solo en catalán. Sin valor por defecto: ausente significa desconocido. | `["es"]`<br>`["es","en"]` |
| `textLanguage` | string | opcional | Idioma en que está escrito el texto libre de ESTE DOCUMENTO — `name`, `description` y cualquier otra prosa que lleve. Una sola etiqueta BCP 47, no una lista: un texto está escrito en un idioma. Es una pregunta distinta de `languages`, que dice qué se habla en el evento. Ausente significa desconocido, nunca el idioma del feed ni el inglés. Dentro de un feed, el evento que lo omite hereda el del feed. | `"es"`<br>`"ca"`<br>`"en"` |
| `offers` | object[] | opcional | Cuánto cuesta asistir y dónde registrarse. Es una lista: cada tipo de entrada (early bird, estudiantes, patrocinio) es una entrada, y un evento gratuito es una sola entrada con `price` 0. Ausente significa DESCONOCIDO, nunca gratis — decir «gratis» es lo que hace `price: 0`. | `[{"price":0,"url":"https://rustmadrid.example/meetups/2026-06#registro"}]`<br>`[{"name":"Early bird","price":35,"currency":"EUR","url":"https://devfest-levante.example/2026/entradas","availability":"sold-out","closesAt":"2026-07-31T23:59:59+02:00"},{"name":"General","price":45,"currency":"EUR","url":"https://devfest-levante.example/2026/entradas","availability":"in-stock"}]` |
| `offers[].name` | string | opcional | Cómo se llama esta entrada («General admission», «Estudiantes»). Merece la pena escribirlo cuando hay más de una oferta; es ruido cuando solo hay una. | `"General admission"`<br>`"Estudiantes"` |
| `offers[].price` | number | opcional | Importe por asistente, en `currency`. 0 significa gratis — y es la ÚNICA forma de decirlo: una lista `offers` ausente significa que el precio se desconoce. Es un número, nunca texto: sin símbolo de moneda, sin separador de miles, sin rangos ni «desde», porque la razón de publicar un precio como dato es que alguien pueda filtrar y comparar con él. Un precio que no se puede escribir con un número son varias ofertas. | `0`<br>`45`<br>`12.5` |
| `offers[].currency` | string | opcional | Código ISO 4217 alfa-3, en mayúsculas (`EUR`, `USD`, `MXN`). Obligatorio siempre que `price` sea mayor que 0, e innecesario cuando es 0: lo gratis es gratis en cualquier moneda, y emitirla ahí es como Luma acaba publicando una divisa para un meetup que no cuesta nada. | `"EUR"`<br>`"USD"` |
| `offers[].url` | string (uri) | opcional | Dónde se compra la entrada o se hace el registro de ESTA oferta. Distinta de la `url` del evento: esa página lo describe, esta es donde cambia de manos el dinero o la plaza. Se omite cuando el registro ocurre en la propia página del evento. | `"https://devfest-levante.example/2026/entradas"` |
| `offers[].availability` | enum: in-stock \| sold-out | opcional | Si esta oferta se puede coger todavía. SIN VALOR POR DEFECTO: ausente significa desconocido, nunca disponible — un feed desactualizado que sigue afirmando `in-stock` es peor que uno que no dice nada. Solo se modelan los dos estados sobre los que quien asiste puede actuar. | `"in-stock"`<br>`"sold-out"` |
| `offers[].waitlistUrl` | string (uri) | opcional | Dónde apuntarse a la cola de esta oferta una vez agotada. Existe para que «agotado y nada que hacer» y «agotado, pero puedes hacer cola» dejen de ser el mismo documento — es la tercera cosa sobre la que quien asiste puede actuar, y la razón de que sea una URL y no un tercer valor de `availability`: así todo consumidor que ya existe sigue leyendo `sold-out`, que es VERDAD, en vez de encontrarse un valor de enum que no sabe interpretar. Distinta de `url`, donde se compra la entrada: en una cola no se compra nada. | `"https://devfest-levante.example/2026/lista-espera"` |
| `offers[].opensAt` | string | opcional | Cuándo sale a la venta esta oferta. Es un INSTANTE, con offset o `Z`, a diferencia de las fechas del evento, que son de reloj de pared: una venta que se abre es el momento en que un botón empieza a funcionar, no una hora en un cartel. | `"2026-05-01T10:00:00+02:00"` |
| `offers[].closesAt` | string | opcional | Cuándo deja de estar disponible esta oferta. Es un INSTANTE, con offset o `Z`, por lo mismo que `opensAt` — y porque un «23:59» sin offset es el bug clásico de las fechas límite. | `"2026-07-31T23:59:59+02:00"` |
| `offers[].translations` | object | opcional | El `name` de esta oferta en otros idiomas. Local a la oferta a la que pertenece — nunca un espejo posicional de la lista de ofertas. Exige el `textLanguage` del documento, como cualquier otro mapa de traducciones. | `{"en":{"name":"Students"}}` |
| `cfp` | object | opcional | La convocatoria abierta de propuestas del evento — charlas, talleres, papers. Es el único campo de la spec sin equivalente en NINGUNO de los tres formatos de destino: existe porque «qué conferencias están aceptando propuestas ahora mismo» es una pregunta que solo puede contestar quien publica, y hoy se contesta scrapeando. | `{"url":"https://devfest-levante.example/2026/cfp","closesAt":"2026-07-15T23:59:59+02:00"}`<br>`{"url":"https://devfest-levante.example/2026/cfp","opensAt":"2026-05-01T00:00:00+02:00","closesAt":"2026-07-15T23:59:59+02:00","coversTravel":true,"coversAccommodation":true}` |
| `cfp.url` | string (uri) | **obligatorio** dentro de `cfp` | Dónde se envían las propuestas: el formulario, o la página que describe la convocatoria. Obligatorio: un CFP que nadie puede encontrar no es una convocatoria, y es la única parte que sobrevive a la exportación a cualquier formato, dentro del texto. | `"https://devfest-levante.example/2026/cfp"` |
| `cfp.opensAt` | string | opcional | Cuándo empieza a aceptar propuestas. Es un INSTANTE, con offset o `Z`. Ausente significa que ya está abierta: una convocatoria que aún no ha abierto está anunciada, no publicada. | `"2026-05-01T00:00:00+02:00"` |
| `cfp.closesAt` | string | _recomendado_ | Fecha límite para enviar propuestas. Es un INSTANTE, con offset o `Z`, nunca un «23:59» pelado: qué medianoche es exactamente la pregunta, y «anywhere on Earth» es una respuesta real (`-12:00`) que un campo de reloj de pared no podría expresar. Ausente significa desconocido, no «abierto para siempre» — y es lo que un consumidor necesita para responder «qué CFPs están abiertos ahora». | `"2026-07-15T23:59:59+02:00"`<br>`"2026-07-15T23:59:59-12:00"` |
| `cfp.coversTravel` | boolean | opcional | Si el evento cubre el viaje de quien sea seleccionado. SIN VALOR POR DEFECTO: ausente significa desconocido, nunca `false`. Está aquí, y «call for sponsors» no, porque esto es lo que filtra quien da charlas antes de decidir si se puede permitir enviar una propuesta. | `true` |
| `cfp.coversAccommodation` | boolean | opcional | Si el evento cubre el alojamiento de quien sea seleccionado. Misma regla que `coversTravel`: ausente significa desconocido. | `true` |
| `status` | enum: scheduled \| tentative \| cancelled \| postponed \| rescheduled \| moved-online | opcional | Qué le ha pasado al evento, no al dato. Un evento cancelado, pospuesto o movido a online DEBE seguir publicado: borrarlo deja un evento muerto en el calendario de quien se suscribió. `tentative` significa anunciado pero sin confirmar (el `STATUS:TENTATIVE` de iCal) — existe para que quien importa no tenga que ascender a `scheduled` un evento que nadie ha confirmado, ya que este es el único campo con valor por defecto. | `"scheduled"`<br>`"cancelled"`<br>`"moved-online"` |
| `partOf` | object | opcional | La serie o el evento multi-parte del que este documento es UNA ocurrencia. Es una REFERENCIA, nunca una regla de recurrencia: OTE no genera fechas — quien publica expande la recurrencia en un documento por ocurrencia, cada uno con su `id`, sus fechas y su `status`. Un consumidor que ignore este campo sigue viendo eventos completos y correctos. | `{"id":"https://rustmadrid.example/meetups","name":"Rust Madrid — meetup mensual","url":"https://rustmadrid.example/meetups"}`<br>`{"type":"multipart","id":"https://pyalmeria.example/study-jams/2026-testing","name":"Study Jam de testing en Python (3 sesiones)"}` |
| `partOf.id` | string (uri) | **obligatorio** dentro de `partOf` | Identificador estable de la serie o del evento multi-parte. Mismas reglas que el `id` del evento: una URI bajo un dominio que controle quien publica, acuñada una vez. NO tiene por qué resolver a un documento OTE — es lo que permite a un consumidor agrupar las ocurrencias. | `"https://rustmadrid.example/meetups"`<br>`"https://pyalmeria.example/study-jams/2026-testing"` |
| `partOf.name` | string | opcional | Nombre de la serie o del evento multi-parte, para que un consumidor pueda agrupar sin resolver el `id`. | `"Rust Madrid — meetup mensual"`<br>`"Study Jam de testing en Python (3 sesiones)"` |
| `partOf.url` | string (uri) | opcional | Página que describe la serie o el evento multi-parte en conjunto. | `"https://rustmadrid.example/meetups"` |
| `partOf.type` | enum: series \| multipart | opcional | `series`: ocurrencias independientes que comparten identidad (un meetup mensual). `multipart`: partes de UN SOLO evento celebrado en fechas no consecutivas (un study jam de tres sesiones en sábados no consecutivos, con una sola inscripción). Por defecto `series`, que es la opción tolerante. Cambia la traducción: una serie se convierte en `EventSeries` de schema.org; un evento multi-parte, en un `Event` cuyas partes son su `subEvent`. | `"series"`<br>`"multipart"` |
| `partOf.translations` | object | opcional | El nombre visible de la serie en otros idiomas. Su `id` no se traduce: un identificador con dos grafías son dos series. | `{"es":{"name":"Sesión semanal de programación"}}` |
| `license` | string | **obligatorio** | Licencia de ESTOS DATOS, no del evento. Identificador SPDX (`CC0-1.0`, `CC-BY-4.0`…, lista completa en https://spdx.org/licenses/) o una URL. | `"CC-BY-4.0"`<br>`"CC0-1.0"` |
| `source` | object | opcional | Procedencia. Obligatoria cuando el evento se importó o agregó de otro sitio; se omite cuando quien organiza describe su propio evento: es la fuente. | `{"name":"Rust Madrid","url":"https://calendar.example/ics/rust-madrid","license":"CC-BY-4.0","retrievedAt":"2026-06-01T05:00:00Z"}` |
| `source.name` | string | opcional | Nombre de la fuente (p. ej. «Rust Madrid», «Meetup»), tal y como lo leería una persona. Escríbelo siempre que la fuente tenga nombre propio: quien muestre de dónde salió el dato puede sacar una etiqueta de `url` (su host), pero una etiqueta derivada es una suposición. | `"Rust Madrid"`<br>`"Meetup"` |
| `source.url` | string (uri) | opcional | Enlace a la ficha original, para poder verificar y corregir el dato en origen. | `"https://calendar.example/ics/rust-madrid"` |
| `source.license` | string | opcional | Licencia bajo la que la FUENTE publica el dato. Restringe lo que puede republicarse: declarar una licencia no concede derechos que la fuente nunca dio. | `"CC-BY-4.0"` |
| `source.retrievedAt` | string | opcional | Cuándo se obtuvo el dato. | `"2026-06-01T05:00:00Z"` |
| `updatedAt` | string | _recomendado_ | Instante en que los DATOS del evento cambiaron por última vez — equivalente a `LAST-MODIFIED` de iCal, no a `DTSTAMP` (que marca la generación y cambia en cada exportación). Permite a un consumidor sincronizar de forma incremental: traer solo lo que cambió desde su última lectura. Ausente significa desconocido, no «nunca cambió». | `"2026-06-10T18:00:00Z"` |
| `translations` | object | opcional | El texto libre del mismo evento en otros idiomas, indexado por etiqueta BCP 47. El documento conserva UN texto principal en sus propios campos —el que declara `textLanguage`— y aquí van las versiones de ese texto. Aditivo a propósito: `name` y `description` siguen siendo cadenas, así que ningún consumidor existente se rompe y quien publica en un solo idioma no escribe nada. Nunca una traducción al idioma en que ya está el documento. | `{"es":{"name":"Sesión semanal de programación — Rust Girona","description":"Cada semana nos juntamos en línea para picar Rust un rato."}}` |

### Restricciones

Reglas que el schema impone sobre objetos completos y que el nivel de un campo suelto no puede expresar. También generadas de los schemas: el validador rechaza el documento que las incumple.

- **el documento** — Un mapa de traducciones es inservible si no se sabe en qué idioma está el texto principal: quien lo consume no puede saber qué entrada lo duplica ni a qué está cayendo por defecto. Así que CUALQUIER mapa de traducciones del documento —el del propio evento o uno dentro de image, offers, eligibility o partOf— exige textLanguage. Es el único sitio de esta spec donde un campo depende de que otro esté presente, y vale a cualquier profundidad porque el idioma principal es una propiedad del documento entero, no de cada objeto.
- **el documento** — startDate y endDate tienen que ser de la misma forma: dos fechas de día completo, o dos fechas-hora locales.
- **`image[]`** — Con `translations`, `alt` es obligatorio.
- **`location`** — Requiere al menos uno de: `venue`, `onlineUrl`.
- **`location.address`** — Debe llevar al menos una propiedad.
- **`eligibility`** — Cuando `type` es `"restricted"`, `note` es obligatorio. restricted significa «hay una puerta que el enum no sabe nombrar». Sin note no nombra nada, y quien lo consume solo puede mostrar la palabra: así es como un campo que existe para responder «¿puedo ir?» acaba preguntándolo.
- **`offers[]`** — Requiere al menos uno de: `price`, `url`. Una oferta tiene que llevar un precio o un enlace —lo ideal es los dos—. Una que no lleva ninguno no dice nada que no dijera ya omitir la lista entera; es la misma regla que sigue location con venue y onlineUrl.
- **`offers[]`** — Con `waitlistUrl`, `availability` no puede ser `"in-stock"`. Una lista de espera para algo que todavía puedes comprar no es una lista de espera: la cola solo tiene sentido cuando la oferta se ha agotado. La disponibilidad puede seguir estando AUSENTE: quien sabe que hay cola y no controla el estado de las entradas no debería verse obligado a afirmar que están agotadas para poder mencionarla. Solo se rechaza la combinación incoherente, nunca la incompleta.
- **`offers[]`** — Cuando `price` es mayor que 0, `currency` es obligatorio. Una cantidad distinta de cero sin moneda no es un precio: 45 es otra cosa en EUR, en USD y en MXN, y quien tenga que adivinarlo adivinará la suya.
- **`source`** — Requiere al menos uno de: `name`, `url`. La procedencia tiene que apuntar a algo: un nombre que lea una persona, una URL que siga una máquina, idealmente las dos. Cualquiera de ellas basta, y exigir el nombre sería peor que aceptar la URL: quien importa un `.ics` siempre conoce la dirección que descargó y a menudo no tiene nombre de publicador que leer (el X-WR-CALNAME de iCalendar es opcional), así que el requisito se cumpliría inventándolo. Una fuente inventada es peor que una fuente dada solo como enlace. Misma regla que offers con price y url, y que location con venue y onlineUrl.

## `feed` — Feed

Una colección de eventos OTE publicada en una URL estable. Un formato de intercambio, no una API.

| Campo | Tipo | Nivel | Descripción | Ejemplos |
| --- | --- | :---: | --- | --- |
| `specVersion` | const: "0.3.0" | **obligatorio** | Versión de OTE Spec a la que se adhiere el feed. Aplica a todos sus eventos. | `"0.3.0"` |
| `title` | string | **obligatorio** | Nombre del feed, legible por personas. | `"Eventos de PyAlmería"` |
| `description` | string | _recomendado_ | Descripción breve del feed. | `"Meetups mensuales de Python en Almería."` |
| `url` | string (uri) | _recomendado_ | URL canónica de la comunidad, directorio u organización que publica el feed. | `"https://pyalmeria.example"` |
| `textLanguage` | string | opcional | Idioma en que está escrito el texto libre de este feed — `title` y `description`. Es además el VALOR POR DEFECTO de todo evento que no declare el suyo, y eso es lo que lo hace barato: quien publica en un solo idioma lo declara una vez para todo el fichero y ningún evento lo repite. Ausente significa desconocido, nunca el inglés ni el idioma de la respuesta HTTP. | `"es"`<br>`"ca"` |
| `organizers` | object[] | opcional | Quién organiza los eventos de este feed — VALOR POR DEFECTO de todo evento que no declare el suyo. | `licenseUrl` | string (uri) | opcional | URL del texto completo de la licencia. | `"https://creativecommons.org/licenses/by/4.0/"` |
| `updatedAt` | string | **obligatorio** | Cuándo se generó este feed. | `"2026-07-06T10:00:00Z"` |
| `translations` | object | opcional | El `title` y la `description` DEL PROPIO FEED en otros idiomas. ### Restricciones

Reglas que el schema impone sobre objetos completos y que el nivel de un campo suelto no puede expresar. También generadas de los schemas: el validador rechaza el documento que las incumple.

- **el documento** — Con `translations`, `textLanguage` es obligatorio. Misma regla que en un evento: un mapa de traducciones es inservible si no se sabe en qué idioma está el texto principal. Un feed que traduce su título tiene que decir en qué idioma está ese título.
